## 1. Modèle de données — migration 188

```sql
-- 1) Unités opérationnelles : 1 ligne par activité et par labo (1:1)
CREATE TABLE IF NOT EXISTS unites_operationnelles (
  id SERIAL PRIMARY KEY,
  entreprise_id INT NOT NULL REFERENCES profil_entreprise(id) ON DELETE CASCADE,
  type_technique VARCHAR(12) NOT NULL CHECK (type_technique IN ('activite','labo')),
  activite_id INT UNIQUE REFERENCES activites(id) ON DELETE CASCADE,
  labo_id INT UNIQUE REFERENCES labos(id) ON DELETE CASCADE,
  composant_id INT REFERENCES domaine_composants(id) ON DELETE SET NULL,
  vente_active BOOLEAN NOT NULL DEFAULT true,
  production_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK ((activite_id IS NOT NULL) <> (labo_id IS NOT NULL)),
  CHECK ((type_technique = 'activite' AND activite_id IS NOT NULL) OR (type_technique = 'labo' AND labo_id IS NOT NULL))
);
CREATE INDEX IF NOT EXISTS idx_unites_op_entreprise ON unites_operationnelles(entreprise_id);
```
- Fonction SQL `unites_op_composant_defaut(p_entreprise_id INT, p_type TEXT) RETURNS INT` : `SELECT dc.id FROM domaine_composants dc WHERE dc.domaine_id = (SELECT ac.domaine_id FROM profil_entreprise pe JOIN abonnements a ON a.client_id = pe.client_id JOIN abonnement_config ac ON ac.abonnement_id = a.id WHERE pe.id = p_entreprise_id ORDER BY a.id DESC LIMIT 1) AND dc.type_technique = p_type AND dc.actif ORDER BY dc.ordre, dc.id LIMIT 1` (NULL si aucun abonnement/domaine/composant — toléré partout).
- Triggers `AFTER INSERT ON activites` / `AFTER INSERT ON labos` → `INSERT INTO unites_operationnelles (entreprise_id, type_technique, activite_id|labo_id, composant_id) VALUES (NEW.entreprise_id, …, unites_op_composant_defaut(NEW.entreprise_id, type)) ON CONFLICT DO NOTHING` (entreprise_id est NOT NULL sur les deux tables ; les seeds/scripts qui insèrent en SQL obtiennent leur unité). Suppression = cascade FK.
- Backfill : 1 ligne par activité et par labo existants avec `composant_id = unites_op_composant_defaut(...)` ; **flags laissés à TRUE** (jamais copiés du composant) ; contrôle post-backfill : `COUNT(*) WHERE NOT vente_active OR NOT production_active` = 0 (RAISE sinon).

```sql
-- 2) Rattachement = ARBRE (une seule source par unité destination ; la source est toujours un labo en V1)
CREATE TABLE IF NOT EXISTS unites_operationnelles_liens (
  source_unite_id INT NOT NULL REFERENCES unites_operationnelles(id) ON DELETE CASCADE,
  dest_unite_id   INT NOT NULL REFERENCES unites_operationnelles(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (source_unite_id, dest_unite_id),
  CHECK (source_unite_id <> dest_unite_id)
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_unites_op_liens_dest ON unites_operationnelles_liens(dest_unite_id);
ALTER TABLE labos ADD COLUMN IF NOT EXISTS labo_parent_id INT REFERENCES labos(id) ON DELETE SET NULL;
```
- **Un seul écrivain : les colonnes.** `activites.labo_id` (existante) et `labos.labo_parent_id` (nouvelle) restent la source de saisie ; des triggers `AFTER INSERT OR UPDATE OF labo_id ON activites` et `AFTER INSERT OR UPDATE OF labo_parent_id ON labos` synchronisent les liens : NULL → `DELETE FROM liens WHERE dest_unite_id = unité(NEW)` ; sinon `INSERT … ON CONFLICT (dest_unite_id) DO UPDATE SET source_unite_id = EXCLUDED.source_unite_id`. Les ~30 lecteurs/6 écrivains de `activites.labo_id` et les seeds restent valides sans modification.
- Trigger `BEFORE INSERT OR UPDATE ON unites_operationnelles_liens` : (a) même `entreprise_id` des deux unités ; (b) source de type `labo` ; (c) anti-cycle (`WITH RECURSIVE` en remontant les sources depuis `source_unite_id` ; RAISE si on atteint `dest_unite_id`). Messages RAISE avec codes `CYCLE_INTERDIT`, `SOURCE_NON_LABO`, `ENTREPRISE_DIFFERENTE` (SQLSTATE P0001) — le service les mappe en 400.
- Backfill des liens : `INSERT … SELECT ul.id, ua.id FROM activites a JOIN labos l ON l.id = a.labo_id AND l.entreprise_id = a.entreprise_id JOIN unites_operationnelles ul ON ul.labo_id = l.id JOIN unites_operationnelles ua ON ua.activite_id = a.id ON CONFLICT DO NOTHING` ; pour toute activité dont le labo appartient à une AUTRE entreprise (createActivite ne le vérifiait pas : entrepriseController.js:145-149) : `RAISE NOTICE` + `UPDATE activites SET labo_id = NULL` (tracé dans le log de migration).
